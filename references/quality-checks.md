# 质检问题码表

报告里每个问题都带一个**稳定问题码**，格式为 `前缀 + 三位序号`。同一个码永远只对应一个含义和一个级别，因此可以用于回归对比和抑制。

级别：🔴 **错误**（必须处理，否则不该投稿）· 🟡 **警告**（很可能被编辑部退回或影响评审）· 🔵 **提示**（需作者确认或知悉）

每条问题在报告里还会带：**位置**（文件:行号 / §章节 / 图表对象）、**证据**、**建议**、**规范依据**（期刊 / 字段 / 核对状态 / 来源 URL）。给用户解释问题时，优先引用这几项，不要只复述问题码。

|---|---|---|---|
| `FIG001` | 🔴 | 找不到图片文件 | 补文件或修路径 |
| `FIG002` | 🟡 | 图对象没有对应图片文件（可能是矢量图或外部引用） | 确认是否用了 `\includegraphics` 之外的插图方式 |
| `FIG003` | 🟡 | 图片文件无法读取（损坏或非常见格式） | 用图像工具重新导出 |
| `FIG010` | 🟡 | 图片格式不在期刊允许范围内 | 按 `figures.formats` 转换格式 |
| `FIG011` | 🟡 | 图片宽度超上限 | 缩小显示宽度或重新排版 |
| `FIG020` | 🟡 | **有效分辨率不足** | 见下方说明 |
| `FIG021` | 🔵 | 图片内嵌 DPI 标记偏低 | 部分投稿系统会读元数据里的 DPI，重新导出时把 DPI 标记设对 |
| `FIG030` | 🟡 | 图没有题注 | 补题注 |
| `FIG031` | 🔵 | 有子图但缺子图标注 | 补 `(a)(b)(c)` 并在题注中逐一说明 |
| `FIG040` | 🟡 | 同一张图片被多个图对象重复使用 | 确认是否应为不同子图 |
| `FIG050` | 🟡 | 图在正文中没有任何引用 | 期刊普遍要求每个图都被正文显式提及（"as shown in Fig. 2"） |
| `FIG060` | 🔵 | 完全没解析到本地图片，图片质量检查已跳过 | 检查图片路径；这一项说明"没检查"，不是"检查通过" |

### 关于 `FIG020` 的有效分辨率

报告给出的不是文件里的 DPI 标签，而是**有效分辨率 = 像素宽度 ÷ 印刷宽度（英寸）**。证据里同时给出：

- 像素尺寸（如 `1800×1200 px`）
- 印刷宽度及其**来源依据**（Word 显示宽度 / `\includegraphics[width=]` / 按版心估算）
- 颜色数，以及据此判定的"线条图 / 照片"

**DPI 数值本身不能单独决定质量**：一张 300 dpi 的图印到 2 cm 宽可能只有 200 px，反而更差。所以解释问题时要把这几个数一起讲，并说明线条图（阈值通常 600–1200）和照片（阈值通常 300）标准不同。

### `REF030` vs `REF031`：普通文本 vs 结构化字段

Word 稿件的参考文献有两种来源，可靠度差别很大：

- **结构化文献字段**（EndNote/Zotero 等写入的域代码）→ `REF031`，字段齐全，可较可靠地转换。
- **普通文本**（作者手打的编号列表）→ `REF030`，只能按编号/年份切分解析，**必须人工确认**。

报告中会分别统计条数。看到 `REF030` 就要提醒用户逐条核对，不要当成已解析成功。

### 模板压缩包（`CVT011` ~ `CVT013`）

`--template` 可以直接给官网下载的模板压缩包（`.zip`），不需要先手工解压。系统会解包、挑出包内主文件（`.tex` / `.docx`），并把包内**主文件同目录**的 `.cls`/`.bst`/`.sty` 随结果包一起提供，保证可独立编译。

- 包内**只有一份**主文件 → 直接用，无提示。
- 包内有**同族版式**（文件名剥掉 `sc`/`dc`、`1col`/`2col`、`num`/`harv` 这类版式标记后同名同目录）→ **每份各产出一个结果包**，目录名带版式后缀（`journals/template-only-sc/`、`...-dc/`）。Elsevier CAS 的单栏双栏、elsarticle 的数字制著者年制都是这一形态。同族最多展开 4 份，只对 LaTeX 生效。
- 包内有多份候选但**不构成同族**（如模板 + 说明书）→ 报 `CVT013` 并列出候选，**这一条必须人工过目**，别默认选对了。
- 想指定用哪一份 → `--template kit.zip::elsarticle-template-num.tex`（指定后不展开变体）。
- 主文件识别用「命名分档 + 体积」：`template`/`main`/`manuscript` 加分，`sample`/`example`/`doc`/`manual` 减分。**不能只看体积**——官方 kit 里最大的合法文档常常是说明书（实测 CAS 包 18.5 KB 的 `elsdoc-cas.tex` vs 4.9 KB 的真模板）。
- 包内 `readme`、作者须知、`__MACOSX` 垃圾等一律不复制，避免污染结果包。

### `LTX100` 是"没做"，不是"通过"

本机没装 TeX 发行版时，编译与 PDF 预览被跳过，报告里出 `LTX100` 并写明原因。**不要把它当作"编译通过"**，要明确告诉用户："已做静态检查（括号、环境、引用、资源路径），但未做真实编译，建议在装了 TeX 的环境复核一次。"

## 报告怎么读

1. 看**结论**：有 🔴 错误就必须先处理。
2. 看**检查项与结果表**：确认每个类别是"通过"还是"有几项问题"，也确认哪些检查因工具链缺失被跳过。
3. 看**问题明细**：按级别分组，每条带位置、证据、建议、规范依据。
4. 看**需人工确认清单**：需要作者提供信息或做决定的项（补声明、核对普通文本文献、压缩超长正文等）。
5. 看**规范来源附录**与**工具链**：确认判定依据和"哪些检查真的跑了"。
